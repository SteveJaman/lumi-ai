The core difference between Lumi and Neuro is not intelligence.
It is ARCHITECTURE. Neuro runs continuously, has internal state,
makes its own decisions, and acts without being prompted.

Lumi waits. Neuro lives.

Every item below closes that gap. Ordered by dependency —
later items assume earlier ones are done.

================================================================
  PHASE 9 — SECURITY HARDENING                        NOT STARTED
================================================================

Goal: Close attack surfaces across Phases 1-10. The threat
model is not a remote attacker — it's (a) malicious content
Lumi reads, (b) a malicious external app that connects to the
SDK, (c) accidental self-modification, and (d) other local
processes or browser tabs reaching the web client.

  In scope:   prompt injection via file/web/memory/SDK content;
              SDK hijacking; self-modification; API key
              exposure; command escalation; network exposure;
              CSRF and DNS-rebinding against the web client;
              session hijacking via malicious browser extension.
  Out of scope: kernel compromise, hardware attacks, physical
              access, supply-chain attacks on Ollama.

================================================================
  PHASE 10 — LOCAL WEB CLIENT                        MVP SHIPPED
================================================================

Goal: Replace the terminal as the primary product surface.
A fully-offline localhost web application at 127.0.0.1:5000
that serves as THE hub for everything Lumi. Target audience
is a non-technical user: every setup step that currently
requires editing a code file becomes a form. Terminal remains
available as a developer tool, but the default experience is
the browser.

Architecture (as built):
  Browser → http://127.0.0.1:5000  (aiohttp + python-socketio)
       ├─ HTTP routes: /auth/*, /api/*, /api/memories/*,
       │               /setup-status, static /web/*
       ├─ Socket.io on same origin (best-effort, used by the
       │               legacy control panel; the SPA itself
       │               polls HTTP and does not depend on it)
       └─ Static assets served from web/
  Browser → direct link to log_hub dashboard at 127.0.0.1:5001
  Backend → Lumi core (prompter, memory, emotional_state,
              self_model, vtubeStudio) — HOST refactored
  Terminal → optional debug client, same signals

Storage (as built):
  memories/users.db   (SQLite) — user rows, argon2id hashes,
                                  session tokens
  memories/chroma.db  (ChromaDB) — memory facts with metadata

Stack (as built):
  - Backend: aiohttp + python-socketio
  - Auth DB: sqlite3 stdlib
  - Hashing: argon2-cffi (falls back to pbkdf2_hmac)
  - Frontend: plain HTML/CSS/JS. No framework, no build step.
  - Design system: web/style.css — token-based CSS with
    palette, spacing, radius, shadows, buttons, inputs,
    cards, modals, empty states, chat, memory table.
