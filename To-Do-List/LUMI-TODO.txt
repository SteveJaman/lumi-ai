  Notable delta since last update (2026-09-28 PM3):
    - PHASE 7.1 SUPERSEDED. The C# sidecar plan was the
      workaround for a problem that no longer exists. The
      Python `davey` module (the same Rust implementation
      used by @snazzah/davey in AIRI's TypeScript bot) is
      installed alongside discord.py 2.7+ and exposes the
      DaveSession that discord.py negotiates on the
      connection object. We read it lazily and decrypt in
      the sink. No sidecar needed.

    - PHASE 7.2 SHIPPED (Python receiver).
      modules/discordClient.py now has:
        · DaveDecryptor — reads vc._connection.dave_session,
          decrypts each Opus frame via davey.MediaType.audio,
          passes through when session isn't ready.
        · OpusDecoderPool — one discord.opus.Decoder per
          SSRC. Opus decoders carry inter-frame state, so
          mixing speakers through one decoder corrupts both.
        · LocalAudioSink with wants_opus() -> True.
          The extension's PCM path decodes ciphertext into
          noise, so we bypass it entirely.
        · RMS VAD with hysteresis (start 0.020, stop 0.010).
          Replaced the original peak-amplitude VAD which was
          too spiky and merged utterances across pauses.
        · silence_ms = 500, min_speech_ms = 250.
          Matches the local mic path's feel.
        · faster-whisper transcribe on 16 kHz mono PCM.

    - PHASE 7.3 SHIPPED (multi-speaker attribution).
      Sink tracks per-user buffers keyed by user.id, so
      transcripts are correctly attributed even when two
      people overlap. signals.add_message() now accepts
      speaker= and source= kwargs that persist in history
      JSONL for later reflection. last_voice_speaker is
      updated on every transcript.

    - PHASE 7.4 SHIPPED (group context).
      signals.voice_context dict is populated by
      DiscordClient and read by the prompter. Contains:
      guild_name, channel_name, roster (list of
      {id, display_name, is_bot}), human_count, mode
      ("solo" | "group"). Prompter injects a
      [Discord Voice Context] block on every turn that
      changes how the persona addresses the room.
      Persona rule added to lumi.yaml: GROUP AWARENESS.

    - PHASE 7.5 SHIPPED (roster awareness).
      DiscordClient hooks on_voice_state_update to refresh
      the roster whenever someone joins, leaves, or moves
      in a guild we're connected to. Roster pushes through
      to signals.voice_context immediately. Cleared on
      !leave and on shutdown.

    - MIC INPUT BYPASS. MicInput no longer loads its own
      Whisper model when audio_mode is "discord". Saves
      ~1 GB RAM and several seconds of startup.

    - LOG HUB ROUTING. STT transcripts, Discord text
      messages, connection events, and errors all go to
      the log hub under the "mic" and "discord" categories
      instead of spamming the terminal. New "discord"
      category chip on the dashboard.

    - FFMPEG PATH FIX. A broken conda ffmpeg.exe shim
      was shadowing the working winget install and
      silently breaking every send. `where.exe ffmpeg`
      now resolves to the working binary. Same fix
      unblocks pydub and any other FFmpeg consumer.

================================================================
  PHASE 7 — DISCORD VOICE BRIDGE                    ✅ COMPLETE
================================================================

Goal: Enable Lumi to hear and attribute Discord voice
channel audio in real time, and speak back through the same
channel.

The original plan called for a C# sidecar because the
Python ecosystem had no working DAVE decryption at the
time. Since then, the `davey` Rust library was ported to
Python and discord.py 2.7 integrated it for the send path.
That made a pure-Python solution possible, and this is
what shipped.

[X] 7.1  C# sidecar — Discord client joins VC and receives
         SUPERSEDED. No sidecar needed. The Python `davey`
         module provides the same Rust implementation used
         by AIRI's TypeScript bot (@snazzah/davey). Combined
         with discord.py 2.7's DAVE negotiation on the
         connection object, we decrypt in-process.

[X] 7.2  Python receiver module                          DONE
         Files:     modules/discordClient.py
         Status:    DaveDecryptor + OpusDecoderPool +
                    LocalAudioSink with RMS VAD. Reads

Known minor limitations:
  - DAVE drops ~15-20% of frames on session boundaries.
    This is universal, not a bug. The middle of each
    utterance always decodes cleanly.
  - Never disconnect/reconnect the voice client at
    runtime. Reconnects leave the DAVE session out of
    sync with the sink and it goes deaf silently. If
    receive fails, restart the process.
  - Single-channel at a time. The bot can be in one
    voice channel per guild. Multi-guild support works
    because each guild gets its own connection and sink.

  PHASE 9 — SECURITY HARDENING                        NOT STARTED
================================================================

Goal: Close attack surfaces across the entire stack. The
threat model is not a remote attacker — it's (a) malicious
content Lumi reads, (b) a malicious external app that
connects to the SDK, (c) accidental self-modification, and
(d) other local processes or browser tabs reaching the web
client.

  In scope:   prompt injection via file/web/memory/SDK
              content; SDK hijacking; self-modification;
              API key exposure; command escalation; network
              exposure; CSRF and DNS-rebinding against the
              web client; session hijacking via malicious
              browser extension.
  Out of scope: kernel compromise, hardware attacks,
              physical access, supply-chain attacks on
              Ollama.
