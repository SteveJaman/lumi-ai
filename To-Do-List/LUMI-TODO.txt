The core difference between Lumi and Neuro is not intelligence.
It is ARCHITECTURE. Neuro runs continuously, has internal state,
makes its own decisions, and acts without being prompted.

Lumi waits. Neuro lives.

Every item below closes that gap. Ordered by dependency —
later items assume earlier ones are done.

  The core agentic loop is stable and self-correcting.
  Lumi runs autonomously on a timer, reacts to events with
  runtime emotional state, expresses mood through word
  choice and canonical emotion tags, accumulates
  timestamped memories, answers "when did we..." questions,
  perceives what you're working on without being told,
  routes chat through a fast path when it's safe to, keeps
  a persistent self-model of her own patterns, drives her
  own VTuber avatar in real time, and reports her internals
  to a clean dashboard instead of spamming the terminal.

================================================================
  PHASE 9 — SECURITY HARDENING                        NOT STARTED
================================================================

Goal: Close attack surfaces across Phases 1-10. The threat
model is not a remote attacker — it's (a) malicious content
Lumi reads, (b) a malicious external app that connects to the
SDK, (c) accidental self-modification, and (d) other local
processes or browser tabs reaching the web client.

  In scope:   prompt injection via file/web/memory/SDK content;
              SDK hijacking; self-modification; API key
              exposure; command escalation; network exposure;
              CSRF and DNS-rebinding against the web client;
              session hijacking via malicious browser extension.
  Out of scope: kernel compromise, hardware attacks, physical
              access, supply-chain attacks on Ollama.

================================================================
  PHASE 10 — LOCAL WEB CLIENT                        DESIGNED
================================================================

Goal: Replace the terminal as the primary product surface.
A fully-offline localhost web application at 127.0.0.1:5000
that serves as THE hub for everything Lumi. Target audience
is a non-technical user: every setup step that currently
requires editing a code file becomes a form. Terminal remains
available as a developer tool, but the default experience is
the browser.

Scope:
  - User registration and login (local, no internet required)
  - Chat interface as the default landing page
  - First-run setup wizard
  - Persona editor (replaces hand-editing lumi.yaml)
  - Memory browser (replaces !recall exploration)
  - Model manager (replaces ollama CLI)
  - Integration setup (VTS, Discord, browser)
  - Settings (audio, timezone, security, advanced)
  - Dashboard rebuilt as a proper page (not an iframe)
  - Live status pills for VTS, Mic, Ollama in the sidebar

Architecture:
  Browser → http://127.0.0.1:5000  (aiohttp + socket.io,
              already running as socketIO.py)
       ├─ HTTP routes: /auth/*, /api/*, static /web/*
       ├─ WebSocket /chat: authenticated chat protocol
       └─ Static assets served from web/
  Browser → iframe / direct link to log_hub dashboard at
              127.0.0.1:5001 (backend data, custom frontend)
  Backend → Lumi core (prompter, memory, emotional_state,
              self_model, vtubeStudio) — HOST refactored
  Terminal → optional debug client, same signals

Design system (prerequisite for any UI work):
  A single token-based CSS system. One palette
  (GitHub-dark inspired), one spacing scale (8px base),
  one component library (buttons, inputs, cards, tabs,
  empty states, loading skeletons, error states).
  Dark theme default. No framework, no build step.
  Static mockup of chat + setup wizard before any
  backend code so the visual language is validated
  before anything depends on it.

Storage:
  memories/users.db  (SQLite)  — user rows, argon2id hashes,
                                   session tokens, profiles
  memories/chroma.db (ChromaDB) — tagged with user_id for
                                   per-user isolation (10.10)
  users/<username>.yaml — per-user persona overrides
                                   (optional; MVP uses shared
                                   lumi.yaml with <host> template)

Stack decisions (locked):
  - Backend: aiohttp + python-socketio (already in use)
  - Auth DB: sqlite3 stdlib
  - Hashing: argon2-cffi
  - Frontend: plain HTML/CSS/JS. No Node.js, no build step,
    no framework. All files in web/.
  - Icons: Lucide or Feather as inline SVG. One family only.
  - Dashboard: custom-built page, not iframe.
  - Concurrency: one active user at a time. Login switches
    HOST. Terminal and web UI share signals.
