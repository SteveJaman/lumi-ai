The core difference between Lumi and Neuro is not intelligence.
It is ARCHITECTURE. Neuro runs continuously, has internal state,
makes its own decisions, and acts without being prompted.

Lumi waits. Neuro lives.

Every item below closes that gap. Ordered by dependency —
later items assume earlier ones are done.

================================================================
  PHASE 10 — LOCAL WEB CLIENT                        DESIGNED
================================================================

Goal: Replace the terminal as the primary interaction surface.
Run a fully-offline localhost web application that serves a
user registration flow, a chat interface, an embedded
diagnostics dashboard, and a settings panel. All assets
vendored locally — no CDN, no external fonts, no outbound
requests. Works with zero internet after install.

Security posture — be honest about this: binding to 127.0.0.1
eliminates remote internet attackers, but does NOT protect
against other processes on the machine, cross-origin DNS-
rebinding from a browser tab, malicious browser extensions,
or physical access. Real auth hygiene is required: argon2id
password hashing, HttpOnly + SameSite=Strict session cookies,
CSRF tokens on state changes, Origin checks on WebSocket
handshake. "Localhost" is threat-reduced, not threat-
eliminated.

Architecture:
  Browser → http://127.0.0.1:5000  (aiohttp + socket.io,
              already running as socketIO.py)
       ├─ HTTP routes: /auth/register, /auth/login,
       │   /auth/logout, /auth/me, static /web/*
       ├─ WebSocket /chat: authenticated chat protocol
       └─ Static assets served from web/
  Browser → iframe http://127.0.0.1:5001 (log_hub dashboard,
              unchanged — reused as-is)
  Backend → Lumi core (prompter, memory, emotional_state,
              self_model, vtubeStudio) — untouched
  Terminal → still functional as an optional debug client

Storage:
  memories/users.db  (SQLite)  — user rows, argon2id hashes,
                                   session tokens, profiles
  memories/chroma.db (ChromaDB) — tagged with user_id for
                                   per-user isolation (10.9)

Stack decisions (locked):
  - Backend: aiohttp + python-socketio (already in use)
  - Auth DB: sqlite3 stdlib
  - Hashing: argon2-cffi
  - Frontend: plain HTML/CSS/JS. No Node.js, no build step,
    no framework. All files in web/.
  - Dashboard: iframe of log_hub (5001) as-is.
  - Concurrency: one active user at a time. Login switches
    HOST. Terminal and web UI share signals, but only one
    account is "logged in" to Lumi at any moment.
